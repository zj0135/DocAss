## 交付

提供方支持四类 API、多模型、独立视觉能力、上下文窗口、输出预留、兼容参数、默认设置、密钥更换和可取消的草稿测试。密钥由宿主 DPAPI 保管；每次生成冻结配置，排队和在途配置不被后续修改影响。前端 pi adapter 强制使用本机地址；宿主只接受协议白名单路径，重建认证头，禁止重定向，流式转发并传播取消。

每个文档持有独立 ChatSession，切换标签不终止生成，全局最多两个 run，第三个排队且可取消。消息使用自有 DTO、稳定 ID 和父子分支，按 500 ms／32 KiB checkpoint 保存，停止和结束立即落库。会话初始加载最近 50 条，历史按 50 条分页；图片外置，生成前仅临时 hydrate。未完成 checkpoint 恢复为 interrupted，不自动重发。

上下文把系统规则与文档数据隔离，以 UTF-8 字节作保守估算，预留输出和 10% 空间，图片额外计入 8192；超限按完整回合裁剪，保留工具调用与结果配对。小文档在 40% 阈值内可内联；大文档只取就绪页摘要，不为摘要启动全文 OCR。

六个只读工具与创建标注工具绑定 run 原始文档。页数、文字、命中、图像、调用次数和 schema 均有上限；OCR 使用独立订阅。AI 标注和 tool_effects 同事务提交，重复引文必须有当前 run 签发并验证的 anchorToken，否则返回歧义候选。结果关联消息、标注和撤销组。

文字“问 AI”仅进入草稿；框选具有八个控制点，离屏读取原图并裁剪、提取区域文字、显示真实缩略图。模型无视觉时仅发送可用文字，无文字时明确阻止发送。引用点击重新核对版本和范围，被拒绝的 token 不会退回普通引文匹配并画出精确高亮。

## 复现

1. 按根 README 安装锁定依赖并生成基础 PDF、OCR 样本。运行 `pnpm generate:contracts`、`pnpm build`、`pnpm build:host`。
2. `pnpm test:host`、`pnpm test:web`、`pnpm test:browser`。OCR 既有回归需要第四阶段的生成样本，见 [phase4](phase4.md)。
3. 浏览器测试结束后运行 `pnpm verify:llm`。需要交互式 Windows 桌面，会短暂移动鼠标并操作本应用，测试目录与用户数据隔离。
4. `node docs/validation/verify-plan.mjs` 与 `git diff --check` 检查计划、链接和改动格式；计划检查本身不作为功能验收证据。

## 范围与限制

四协议使用可控本机合成上游和假密钥，经过正式 pi、WebView2、自定义 fetch、宿主代理及存储全路径；没有读取用户密钥，没有验证真实云账户额度、真实模型回答质量或所有兼容服务变体。使用真实服务时，在设置中输入自己的接口、模型和 Key，并执行草稿连接测试。

强杀恢复证明本地已确认 checkpoint 和事务的一致性，不代表云端生成可断点续传。文字与图像采用独立构造样本，不能据此宣称真实文档回答质量已经达标。安全恶意输入全集、长时间内存与最终部署门禁仍对应 A51–A62。

Vite 保留 pi 环境探测中 `node:fs` 被浏览器 externalize 的提示及约 2.3 MB 主 chunk 提示；已在正式 WebView2 验证四 adapter 无导入和运行错误。当前文档摘要与历史压缩使用保守裁剪，不额外调用模型总结。已超预算的单次问题会给出明确提示。
