# DocAss 文档入口

当前实施基线为 2026-11-25 的 v1 设计。原型外观可以复用，真实业务能力按任务逐项接入并验收。

| 文档 | 用途 |
|---|---|
| [v1 实施设计](design-v1.md) | 已确定的技术方案、接口、状态、坐标、持久化、OCR、LLM、性能和发布门禁 |
| [剩余完整工作任务](tasks.md) | a1–a62；每项列出前置依赖、关联需求、交付物与验收目标，末尾有完整需求覆盖索引 |
| [需求编号基线](requirements.md) | F1–F8 与 N1–N13；语义调整以新设计 §2 为准 |
| [设计审核与验证结论](design-review-2026-11-25.md) | 原方案的问题、实测结果及尚未证明的边界 |
| [原型说明](prototype-guide.md) | 五个界面场景、mock 数据与现有交互；不作正式功能完成证明 |
| [历史设计](design.md) | 原始 v0.2 设计与评审回写，仅供追溯 |
| [计划一致性检查](validation/README.md) | 编号、前置依赖、验收字段和需求覆盖检查；不等同产品测试 |
| [第一阶段实施与验收](validation/phase1.md) | A1–A15 实现、自动化验收结果与受控场景的范围说明 |
| [第五阶段实施与验收](validation/phase5.md) | A41–A50：四协议、流式会话、文档工具、AI 标注、附件和引用闭环；合成上游验收边界 |

建议先读新设计 §1–§3 理解决定和原型边界，再按任务清单的阶段推进。A1–A50 的正式工程验收见各阶段记录，四类协议已通过正式 WebView2 与合成上游全路径。真实扫描与模型质量扩展、性能和干净机器部署仍须按后续任务通过门禁；不能仅以 Spike 通过勾选任务。

正式工程入口为根目录 `DocAss.sln` 和 pnpm workspace，运行方法见[项目说明](../README.md)。`docs/spikes`、原型 PNG 和生成证据保留在原工作区，按源码仓库要求排除在 Git 外；历史设计中的相应路径是归档引用。正式验收使用源码中的测试入口重新生成。
